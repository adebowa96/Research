SAS: checking assumptions before a t-test

Before comparing two groups, I test for normality, run the t-test, and then run a nonparametric Wilcoxon rank-sum test as a sensitivity check in case the normality assumption fails. 

/* Test for normality by group */
proc univariate data=SASHELP.FISH normal mu0=0;
  ods select TestsForNormality;
  where Species='Roach' or Species='Parkki';
  class Species;
  var Weight;
run;

/* Two-sample t-test */
proc ttest data=SASHELP.FISH sides=2 h0=0 plots(showh0);
  where Species='Roach' or Species='Parkki';
  class Species;
  var Weight;
run;

/* Nonparametric alternative */
proc npar1way data=SASHELP.FISH wilcoxon plots=wilcoxonplot;
  where Species='Roach' or Species='Parkki';
  class Species;
  var Weight;
run;

SAS: methods I've applied and interpreted

MethodExample finding
Pearson vs. Spearman correlation (PROC CORR)With one extreme outlier in a 10-point dataset, Pearson's r was 0.04 while the rank-based Spearman ρ was 0.42, showing that rank methods are less sensitive to outliers (neither was significant at n = 10).
Point-biserial correlationFlagged a weak test item (r = 0.13, p = 0.21) that didn't separate high and low scorers.
Multiple regression with VIF (PROC REG)Interpreted a predictor (vehicle weight) that was correlated with price on its own (r = 0.45) but not significant once horsepower and length were added (p = 0.89), with only moderate collinearity (VIF 2.7).
Stepwise selection (SBC vs. adjusted R²)A two-predictor model (honor status + spelling score) had a higher adjusted R² than the full model (0.146 vs. 0.143).
Binary logistic regression (PROC LOGISTIC)Above-average study time: unadjusted OR = 13.5 (95% CI 5.2–35.3) for graduating, attenuating to 7.5 (2.1–26.9) after adjusting for English and math grades. Used a UNITS statement to report odds ratios per 5-point grade increase.
Model comparisonAdding English and math grades to the study-time model cut the AIC from 216 to 98.

R: cleaning a health dataset with the tidyverse

A reproducible cleaning script (lightly condensed): check for missing values and duplicates, standardize names and codes, derive BMI categories, restrict to adults, and save an analysis-ready file. 

library(tidyverse)

health_data <- read_csv("Data/health_data.csv")

# Missing values and duplicates
colSums(is.na(health_data))
sum(duplicated(health_data))

# Rename variables and standardize coding
health_data <- health_data %>%
  rename(BloodPressure = SBP, SmokingStatus = smoking) %>%
  mutate(SmokingStatus = recode(SmokingStatus, "yes" = "Yes", "no" = "No"))

# Derived variable: BMI category (keeps missing as missing)
health_data <- health_data %>%
  mutate(BMI_Category = case_when(
    is.na(BMI)  ~ NA_character_,
    BMI < 18.5  ~ "Underweight",
    BMI < 25    ~ "Normal",
    BMI < 30    ~ "Overweight",
    TRUE        ~ "Obese"
  ))

# Adults only, analysis variables only
analysis_data <- health_data %>%
  filter(age >= 18) %>%
  select(age, BMI, BMI_Category, SmokingStatus, diabetes, BloodPressure)

write_csv(analysis_data, "Output/analysis_data.csv")

The follow-up script summarizes the cleaned data with frequency tables and a descriptive summary table from gtsummary::tbl_summary().

Python: parsed doesn't mean valid

In a pandas data-quality exercise I diagnosed a deliberately messy account file before computing any metrics. Each problem got a different decision instead of one blanket cleaning rule:

ProblemDecision
Same ID twice, differing only in how "not churned" was coded (FALSE vs. 0)Confirm the codes mean the same thing, standardize, then treat as a true duplicate
Same ID twice with coordinated changes (seats 5 → 6, revenue 450 → 540)Keep both for now: likely a real update, not a duplicate; confirm what one row represents before deduplicating
"US", "us", "United States"; "pro" vs. "PRO"Standardize categories
A signup date stored as a Unix timestampParse separately, then merge into one date format
Revenue of −99Likely a sentinel code; confirm before setting to missing
Last active in 2099, or before the signup dateParses fine but fails validation; flag, don't guess
Missing company name vs. missing seat countKeep the row; exclude only from analyses that need that field
 
# Parse mixed date formats, handling the Unix timestamp separately
df['signup_date'] = pd.to_datetime(df['signup_ts'], errors='coerce', format='mixed')
unix = df['signup_ts'].str.fullmatch(r'\d{10}', na=False)
df.loc[unix, 'signup_date'] = pd.to_datetime(df.loc[unix, 'signup_ts'].astype('int64'), unit='s')
df['last_active_date'] = pd.to_datetime(df['last_active'], errors='coerce', format='mixed')

# Validation rules: values that parse but can't be true
before_signup = df[df['last_active_date'] < df['signup_date']]
in_future     = df[df['last_active_date'] > pd.Timestamp('2024-03-06')]

The same instinct applies to health records, where a "duplicate" patient row may be a real follow-up visit and an impossible date is a question for the data source, not something to fill in.
