Segmenting and Predicting Responders to an Outreach Campaign

An end-to-end machine-learning project on 11,162 customer records from a bank's phone campaign: SQL exploration, clustering, and classification, with a deliberate choice to keep data leakage out of the model.

Program
Data science course (group project, 13 members)
Data
Bank Marketing dataset (Kaggle)
Tools
Python, pandas, SQLite, scikit-learn, imbalanced-learn
Environment
Google Colab, fixed random seed

Why it's relevant to public health

The data comes from banking, but the question is a common one in public health outreach: with limited staff time, whom should we contact, and when should we stop calling? The same workflow applies to vaccination reminders, screening outreach, and program enrollment.

1. Exploring with SQL

We loaded the data into SQLite and used SQL aggregation to profile response rates. Customers who had said yes in a previous campaign said yes again 91% of the time, versus 41% of those with no prior contact. 

SELECT poutcome,
       COUNT(*) AS n_customers,
       ROUND(100.0 * SUM(CASE WHEN deposit = 'yes' THEN 1 ELSE 0 END) / COUNT(*), 1) AS pct_subscribed
FROM customers
GROUP BY poutcome
ORDER BY pct_subscribed DESC;

2. The leakage decision

Call duration was the strongest predictor: 85% of calls over 10 minutes ended in a "yes", versus 9% of calls under 2 minutes. But duration is only known after the call, so we kept it for exploration and excluded it from every classifier (it was still one of the 13 inputs to the K-Means clustering in section 4, so the segments are not fully free of it).

Using it would have produced impressive scores that are useless for deciding whom to call. We chose the honest, deployable model.

3. Feature engineering

  • Age groups from continuous age.
  • Contacted before (0/1), derived from the "days since last contact" code.
  • Campaign intensity: current-campaign calls relative to previous contacts.
  • Binary and ordinal encoding where order exists, one-hot encoding otherwise. "Unknown" was kept rather than dropped or imputed: as its own one-hot category for job, contact and previous outcome, and as a code of -1 (below "primary") on the ordinal education scale.

4. Customer segments (K-Means)

We clustered customers without using the outcome and chose three clusters based on the silhouette score (0.245, the highest tested). Then we checked how each segment actually responded:

Segments built without the outcome still separated high and low responders. The over-contacted group responded least. That fits call fatigue, but it is an association, not proof: the call count includes the final call, and customers who say yes are presumably not called again, so persistent non-responders build up calls. Response by call number would need checking before any "stop after N attempts" policy.

5. Classification

We compared logistic regression, a decision tree, a random forest, and gradient boosting, using 5-fold stratified cross-validation.

The dummy baseline scored F1 = 0.49 and ROC AUC = 0.51 on the test set. The tree ensembles both ranked prior campaign success, balance, age, day of month, and an unknown contact type highly. These are impurity-based importances, which tend to favor continuous variables such as balance, age and day, and they show what predicts a response, not what causes it.

6. Imbalance handling and the decision threshold

The outcome was nearly balanced (47% yes), so class weighting and SMOTE changed little, as expected. The bigger lever was the decision threshold. A missed responder costs more than an extra call, so we lowered the random forest's threshold from 0.50 to 0.40. That raised recall from 0.62 to 0.75 and F1 from 0.67 to 0.70 on the 20% test split, while precision fell from 0.74 to 0.66. ROC AUC does not depend on the threshold and stayed at 0.77. Because 0.40 was picked as the best-F1 threshold on that same test split, these gains are somewhat optimistic (see next steps).

What I'd do next

  • Choose the threshold on a separate validation fold, so the test set stays untouched for the final score.
  • Tune gradient boosting, which had the best cross-validated AUC, and compare it head-to-head at the chosen threshold.
  • Validate on a later time period instead of a random split, since campaign data drifts.
